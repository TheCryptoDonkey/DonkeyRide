Built for real journeys

One app, different ways to travel

A journey can be a paid job, an informal lift or an ordered multi-stop route. The software does not force every community or market into the same commercial model.

Informal or shared lift

Choose no settlement when no money changes hands, and include each intermediate pickup or drop-off.

Independent driver

Use the installable PWA or signed Android app and discover nearby requests over open Nostr relays.

Licensed operator

A firm can deliberately run the optional managed backend for admission, records, policy and payment integrations.

Private by design, honest about metadata

Less central data is not the same as anonymity

Direct mode removes the DonkeyRide database. Exact journey coordination is encrypted between matched participants, while public discovery is coarse and short-lived. Supporting network services still see some metadata.

Your device holds your identity

Role and operator identities are derived from a locally encrypted identity tree. Public driver discovery uses a separate per-shift key.

The router sees route points

The road service receives ordered coordinates so it can return real distance, time and geometry, but not a DonkeyRide identity or journey ID.

Relays see network metadata

Nostr relays can observe IP addresses, timing, short-lived public keys, coarse cells and encrypted envelope metadata.

Maps and search see requests

Map hosts receive tile requests; the search provider sees the place text a person types and a coarse location bias.

Deployment choice

Direct by default. Managed by choice.

Direct mode

  • No DonkeyRide REST API, WebSocket operator, PostgreSQL or Redis
  • Coarse public discovery; exact details encrypted participant-to-participant
  • Payment can explicitly be “none”

Managed mode

  • A selected firm runs the coordination backend
  • Its published policy decides data handling and retention
  • Optional admission, records and payment integrations

Pick up the app and start

The rider and driver PWAs work in a browser and can be installed to a home screen. Android drivers can also use the signed native app for a persistent on-shift service.

If you want the technical details

These are the ForgeSworn libraries directly used by the current web app:

nsec-tree
Derives separate local rider, driver and operator identities from one encrypted root.
geohash-kit
Represents service areas as compact geographic cells instead of publishing continuous exact locations.

Other dependencies, including nostr-tools, are listed in the source repository. This page names only the ForgeSworn libraries wired into the current web app.
